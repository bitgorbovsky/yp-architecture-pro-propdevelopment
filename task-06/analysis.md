# Отчёт по результатам анализа Kubernetes Audit Log

## Подозрительные события

1. Доступ к секретам:
   - Кто: minikube-user/system:serviceaccount:secure-ops:monitoring
   - Где: Пространство kube-system
   - Почему подозрительно: Запрос секретов системного пространства должен быть
     доступен только специальным пользователям и администраторам кластера.

2. Привилегированные поды:
   - Кто: minikube-user
   - Комментарий: Возможность создания pod'ов с завышенными привилегями
     является серьёзной брешью в безопасности, так как через такие pod'ы можно
     выполнять команды, влияющие на сам кластер и на систему, на которой он
     запущен.

3. Использование kubectl exec в чужом поде:
   - Кто: minikube-user
   - Что делал: пытался вывести содержимое файла /etc/resolv.conf.

!НЕ УДАЛОСЬ ВЫПОЛНИТЬ!

## Вывод

1. Отсутствует разраничние прав доступа к системным ресурсам. Необходимо его ввести.
2. Необходимо создать несколько разных учётных записей для выполнения отдельных задач.
3. Неполнота правил аудита - не все подозрительные события могут попасть в журнал.
4. Неполнота определения нормальных действий - чтобы выделить подозрительные
   события из журнала аудита, необходимо определить, какие действия являются
   допустимыми и нормальными. Этого определения нет, что затрудняет проведения
   аудита в целом.
5. Предоставлена возможность запуска pod'ов c повышенными привилегиями.
   Необходимо ввести контроль правил безопасности с помощью OPA Gatekeeper, с
   помощью которого запретить создание pod'ов с завышенными привилегиями и
   выполнения команд в подах.
